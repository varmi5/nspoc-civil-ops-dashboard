Running it locally

Node 24 or higher is required. This is pinned in .nvmrc.

1. Clone the repository

{% call codeBlock() %} git clone https://github.com/varmi5/nspoc-civil-ops-dashboard.git cd nspoc-civil-ops-dashboard {% endcall %}

2. Install dependencies

{% call codeBlock() %} npm install {% endcall %}

3. Set the environment variables

Copy the example environment file and add the MSH client ID and secret.

{% call codeBlock() %} cp .env.example .env {% endcall %}

Without MSH credentials the dashboard still runs. Every MSH figure shows "No live data source connected" instead of a value. Every variable in .env.example has a comment explaining what it does.

4. Start the dev server

{% call codeBlock() %} npm run dev {% endcall %}

The dashboard runs at http://localhost:3000 and reloads automatically on save.

Repository overview

The dashboard is one GitHub repository, nspoc-civil-ops-dashboard. There is no separate frontend, backend, or infrastructure repository, and no database.

  • app/routes.js, defines every page's URL and what runs when it is requested.
  • app/lib/view-models/, one file per dashboard page, builds the data that page needs.
  • app/lib/msh/, the MSH API client, login handling, caching, and the status logic described below.
  • app/lib/space-weather/, the same, for the NOAA feed.
  • app/views/, page templates, with shared macros in app/views/macros/.
  • app/config/sections.js and app/config/data-sources.js, drive the navigation and the Data sources page.

The dashboard is hosted on Railway. A push to main triggers a deploy automatically.

Pages

Every page follows the same pattern. A route calls a view model, the view model asks getSectionData for its figures, and the status returned decides what is shown. The Re-Entry page is used below as a worked example.

Route

app/routes.js:

{% call codeBlock() %} router.get('/re-entry', async (req, res, next) => { try { const viewModel = await buildReEntryViewModel(req.query.months) res.render('re-entry/index', { viewModel }) } catch (err) { next(err) } }) {% endcall %}

The route does not call MSH directly. It asks a view model for data, then renders a template with the result.

View model

buildReEntryViewModel, in app/lib/view-models/re-entry.js, calls getSectionData rather than the MSH client directly. Every view model does this.

getSectionData

app/lib/msh/get-section-data.js:

{% call codeBlock() %} async function getSectionData (sectionKey, { liveFetcher }) { if (!dataSource.isConfiguredForLive(sectionKey)) { return { data: null, status: STATUS.NOT_CONNECTED } } try { const data = await liveFetcher() return { data, status: STATUS.LIVE } } catch (err) { console.error(`MSH live fetch failed for section "${sectionKey}": ${err.message}`) return { data: null, status: STATUS.UNAVAILABLE, httpStatus: err.httpStatus } } } {% endcall %}

The status returned is always one of three values, defined in app/lib/msh/status.js:

{% call codeBlock() %} const STATUS = { LIVE: 'live', UNAVAILABLE: 'unavailable', NOT_CONNECTED: 'not-connected' } {% endcall %}

This function never returns sample or fixture data. If a fetch fails, data is null and status explains why.

Status badge

app/views/macros/badge.njk turns the status into the tag shown on the page:

{% call codeBlock() %} {% raw %}{% macro mshBadge(status) %} {% if status == "live" %} {{ govukTag({ text: "Live from MSH API", classes: "govuk-tag--green" }) }} {% elif status == "unavailable" %} {{ govukTag({ text: "No data available", classes: "govuk-tag--red" }) }} {% else %} {{ govukTag({ text: "No live data source connected", classes: "govuk-tag--grey" }) }} {% endif %} {% endmacro %}{% endraw %} {% endcall %}

This is the same chain for every page on the dashboard: route, view model, getSectionData, status badge. Only the view model and the MSH endpoint change from page to page.

Calculations

app/lib/view-models/monthly-overview.js calculates month-on-month change with computeDelta:

{% call codeBlock() %} function computeDelta (current, previous, { goodWhenDown } = {}) { if (current === null || current === undefined || previous === null || previous === undefined) { return { text: null, deltaGood: undefined } } const diff = current - previous const pct = previous === 0 ? 0 : Math.round((Math.abs(diff) / previous) * 100) const sign = diff >= 0 ? '+' : '-' return { text: `${sign} ${Math.abs(diff)} (${pct}%)`, deltaGood: goodWhenDown === undefined ? undefined : (diff <= 0) === goodWhenDown } } {% endcall %}

This takes the current and previous month's figures, calculates the difference and the percentage change, and marks the result good or bad using goodWhenDown. A rise in launches is good, a rise in collision risk is not. If either figure is missing, no comparison is shown.

Data sources

Two services provide live data:

  • Monitor Space Hazards (MSH), the main source. Requires a client ID and secret. A separate test version of MSH exists, with its own separate credentials.
  • NOAA SWPC, a public feed used only by the Space Weather page. No login required.

Every figure on the dashboard, its exact endpoint, and its current connection status are listed on the Data sources page.

Decisions

No database

Every page fetches its data when it is requested. Nothing is stored.

Reason: there is nothing to migrate or back up, and every number has to prove where it came from on each request.

No fixture fallback in production

Earlier versions of the dashboard showed sample data when a live fetch failed. This was removed.

Reason: a number is either real or marked missing. It is never a stored guess.

No third-party map provider

The Re-Entry map draws its own grid instead of using a map tile service.

Reason: avoids sending object-tracking queries to an external company.

Country, not coordinates, for re-entry location

Re-entry locations are shown as a country name (e.g. "United Kingdom"), not latitude/longitude, using @rapideditor/country-coder. It looks up the country entirely on the server, from a bundled dataset, with no external request for any coordinate.

Reason: different users mainly need to know whether their own country should be concerned, not exact degrees, and sending OFFICIAL-classified coordinates to a third-party geocoding service isn't an option, the same reasoning behind not using a map tile provider above. The trade-off: this library favours size and speed over precision, and only loosely covers water, so predictions well out at sea often show as "No country (predicted over ocean)" rather than a nearest country.

Open questions

  • The collision risk figure reported for the current month does not match NSpOC's own reported figure. No MSH endpoint currently produces the narrower figure NSpOC reports.
  • Space weather ratings are a first draft. NSpOC has not signed off on them.
  • Space weather uses NOAA, a US feed. MOSWOC, the Met Office's own service, has been identified as the correct source. This has not been implemented.
  • There is no automated test suite. Changes are checked manually, and with the scripts in scripts/.
  • There's no per-month "alert" figure for conjunctions from MSH, unlike re-entries, which get alert_count directly from MSH's monthly endpoint. The conjunction trend cards instead show events past the analysis threshold that month, bucketed from the current outstanding-review queue and labelled "needing analysis" rather than "alerts". Because that queue only ever holds currently-outstanding events, a month's count can still drop later as those events get resolved, so it's an approximation, not a true historical total. Fragmentation's trend has no equivalent figure at all yet.

Why the monthly collision figure runs high

"Collision Risks (This Month)" on the Monthly Overview page counts every screened object pair MSH recorded that month. It's typically much larger than NSpOC's own reported monthly figure. Monthly volume is volatile too, one month measured 2,357 against 40,000 to 78,000 in the surrounding months, so a fair comparison depends on which month you check.

Two causes we've ruled out:

  • Duplicate CDM revisions: we tested a 2,000-event sample and found none.
  • A missing UK filter: 91.8% of events already involve a UK-licensed object, so this data is UK-scoped by construction, not global.

We checked MSH's full API spec directly. No endpoint or filter produces the narrower, analyst-reviewed figure NSpOC reports. The closest candidate, a report filter on a different endpoint, returns close to zero rows a month, nowhere near NSpOC's figure either. We've raised this with the MSH/NSpOC team.

Glossary

  • Conjunction, a predicted close pass between two objects in orbit.
  • Fragmentation, when an object breaks into multiple pieces, from a collision or otherwise.
  • CDM (Conjunction Data Message), an official warning about a possible collision. The same event can get several CDMs as new information comes in.
  • TCA (Time of Closest Approach), when two objects are predicted to be nearest each other.
  • Epoch, a fixed point in time used as a reference for orbital data.
